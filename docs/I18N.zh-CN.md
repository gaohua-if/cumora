# 国际化

UI 内置英文与简体中文(`zh-CN`)。语言是按设备选择的:桌面端在 **Preferences → Language**,移动端在 **You → Language**,切换后立即生效——每个通过 `useT()` 读取文案的组件都订阅了 locale store,因此没有刷新,也没有"重启后生效"。

首次运行且没有已存储的选择时,由浏览器语言决定:任何 `zh*` 标签落入简体中文,其余落入英文。

> 本文件是 [I18N.md](I18N.md) 的简体中文翻译;如与英文原文有出入,以英文原文为准。

## 工作原理

三个文件,零依赖:

| 文件 | 职责 |
|---|---|
| `src/lib/i18n.ts` | locale store(zustand + `localStorage`,与 `stores/sound.ts` 同构)、查找、`{name}` 插值 |
| `src/locales/en.ts` | 英文词条目录——**事实来源(source of truth)** |
| `src/locales/zh-CN.ts` | 中文词条目录,以 `en` 作为类型约束 |

`en` 为其他所有 locale 提供类型,所以译错一个 key 或凭空发明一个 key 都会在 `tsc` 处失败,而不是渲染出空白。某个 locale 尚未翻译的 key 会回退到英文——这意味着一份未完成的翻译呈现的是中英混排的界面,而不是空界面。未完成是 locale 的常态,不是 bug。

## 在组件中使用

```tsx
import { useT } from '@/lib/i18n'

function Greeting({ name }: { name: string }) {
  const t = useT()
  return <div>{t('common.greeting', { name })}</div>
}
```

`useT()` 是一个 hook:locale 变化时它会触发组件重渲染。对于模块作用域或不触发渲染的事件处理器,可用 `t()`(非响应式导出)一次性读取当前 locale。

在模块作用域定义的数据——导航项、偏好设置行——存储的是**消息 key** 而不是字符串,并在渲染时解析:

```tsx
const tabs: Array<{ key: string; label: MessageKey }> = [
  { key: 'profile', label: 'me.tab.profile' },
]
```

注意上面 `key` 与 `label` 的区分。任何标识状态的东西(一个标签页、一个偏好项、一条路由)都必须保有一个不随语言变化的标识符;只有 label 才被翻译。

## 添加一个词条

1. 把 key 加进 `src/locales/en.ts`,附英文文案。key 的格式是 `area.thing`——area 对应文案所在的位置(`nav.`、`auth.`、`me.`、`mobileMe.`),通用措辞放在 `common.` 下。
2. 在组件里使用 `t('area.thing')`。
3. 在 `src/locales/zh-CN.ts` 中翻译它。暂时不翻译也安全——它会先以英文渲染,直到有人补上。

## 添加一种语言

1. 复制 `src/locales/zh-CN.ts` 为 `src/locales/<code>.ts`,保留 `Partial<Record<keyof typeof en, string>>` 类型,翻译对应的值。
2. 在 `src/lib/i18n.ts` 中注册:把代码加入 `Locale` 联合类型,把字典加入 `DICTS`,并在 `LOCALES` 中加一条(其 `label` 用该语言的自称——找中文的人扫描的是"简体中文",而不是 "Chinese (Simplified)")。
3. 如果该语言需要自动检测,扩展 `detectLocale()`。

语言选择器本身无需改动;它从 `LOCALES` 渲染。

## 当前覆盖情况

词条目录已完整镜像:`zh-CN` 拥有 `en` 的每一个 key,且每个界面都通过 `useT()` / `t()` 读取——会话、看板、日历、文档、智能体与 Shipping 视图、移动端各屏,以及管理后台,一概在内。自身不渲染文本的组件(`Select`、`ContextMenu`、peek 面板)接收的则是已翻译好的字符串 props,因此它们内部不存在隐藏的英文。

这并不意味着英文回退退役了:新加进 `en` 的 key 会先以英文渲染,直到它的 `zh-CN` 值补上。所以新 key 应当与它的 `zh-CN` 翻译在同一个 PR 中交付,以保持镜像完整。

服务器生成的文本(智能体回复、摘要、邮件)是另一个问题:它来自模型提示词,而不是这份词条目录。
