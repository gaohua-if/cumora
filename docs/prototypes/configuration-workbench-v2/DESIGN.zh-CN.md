# Cumora 配置工作台设计

2026-10-05。设计基线为[原型 v2](../configuration-workbench-v2.html)与[交互决策](../configuration-workbench-v1/DECISIONS.zh-CN.md)。目标是把四类配置组织成日常可使用的桌面页面，并与现有群聊、固定定义版本及 Task 快照保持一致。

## 范围与页面

三栏分别为配置分类、对象列表、对象详情。分类为 Agent、Access Bundles、群聊、Skill 库；工作区执行模式与本地准入保持为独立执行配置入口。群聊复用 `conversations` 与 `conversation_members`，Agent 复用 `participants`，每群成员配置复用 `channel_agent_bindings`，不另建 Channel 或 Agent 身份体系。

Agent：基本信息、基础提示词、已选固定 Skill 版本、默认语言/模型、本地计算机与引擎。Skill：名称、标识、场景、Markdown 内容、版本与引用位置。Bundle：名称、说明、默认身份、MCP/域名/GitHub 资源项及使用说明。群聊：共同规则、响应/输出/语言/并行/记忆偏好、默认负责人、成员别名与补充要求、Skill 增加/禁用/升级、资源包引用及成员访问模式。

新建群聊默认包含工作区 Aida，专业 Agent 为可选成员；单 Aida 与多个 Agent 使用同一种群聊配置模型。保存与撤销有明确状态，切换对象时处理未保存编辑。撤销后选中对象必须存在，失效对象不能继续编辑。

## 版本与发布

Agent 定义使用 `agent_definition_versions`；Skill 增加不可变发布版本表；Bundle 扩展现有 `access_bundle_versions` 的配置内容，不用展示名称代替版本标识。Agent 的 Skill 引用、Binding 的额外 Skill 引用、群聊的 Bundle 引用均记录发布版本 ID。

发布新版本保留旧内容；只改变该对象的最新发布版本。已有群聊、Agent 的 Skill 引用不自动升级。当前版本与最新版本同时展示，独立升级动作确认目标版本，取消或普通选择确认不能暗中升级。

保存群内局部配置只更新当前 Binding；不反写基础定义。Skill 从选择器导入时保留成员上下文和选择草稿，返回原选择器勾选新 Skill，确认后才改动引用。导入创建工作区 Skill，关闭选择器不应隐式绑定到成员。

## 生效配置解析

服务端提供唯一解析投影。语言按成员显式值、群聊具体语言、固定 Agent 默认、工作区默认、产品明确默认依次解析。继承标记表示未指定，不能循环返回前一层。预览展示最终值和来源。

Skills 从固定 Agent 版本继承，应用群内禁用 ID，再叠加群内固定引用；同 ID 的群内引用替代继承引用。提示词按基础职责、群聊共同规则、选中 Bundle 使用说明、成员补充要求组成，并显示来源。自由文本冲突不自动猜测或改写。

访问模式 `all` 继承群聊全部引用，`subset` 选择当前引用中的部分，`none` 不使用外部资源。删除群聊引用只移除失效子集项，`subset` 删空保持空集合。资源包引用不创造执行授权。

Bundle 默认身份只用于没有显式身份的连接。连接显式身份优先；域名不附带登录凭证。逐资源投影包含类型、包与版本、实际身份及来源、MCP URL/工具、域名/端口、GitHub 仓库/分支/路径/动作及连接状态。

## 与执行数据流衔接

保持 Channel → Binding → Task → Execution Context → Runtime → Artifact → Delivery 的现有路径。根任务与子任务创建时固定解析配置，指令中携带已选 Skill 内容、语言与共同规则；旧任务及其执行上下文不读取最新配置替换原内容。

配置发布/升级与成员移除、执行位置变化、授权撤销分开处理。前者影响新任务，后者继续经过现有实时校验。现有 `editBinding` 会撤销执行上下文、执行解析比较 Binding 版本；新实现必须区分普通配置修订和执行资格修订，不能为了旧快照而取消成员或 Runtime 的实时检查。

MCP、Domains、GitHub 本轮实现配置管理、版本、身份/范围投影与 Task 配置快照；真实连接凭证、外部 adapter 执行不由配置页面隐式创建。连接尚未准入时明确显示状态，不能将保存成功展示为连接已可执行。保持现有第一方 channel adapter 的执行边界。

## API 与一致性

在现有 `/tasks` 路由增加配置工作台 API，读返回真实工作区对象及版本，写操作发布定义/Skill/Bundle、保存群聊/Binding、明确升级引用与管理资源项。沿用现有创建 Agent、创建群聊、成员管理接口以及本地计算机选择流程。

新增版本表与配置字段通过向前数据库迁移引入，不修改既有迁移 SQL/checksum。每次写在现有工作区事务锁内校验租户、对象引用及版本，使用修订号防止多人编辑覆盖；冲突时保留用户草稿并提示重新载入。失败不显示已保存；刷新必须从服务端读回。保存、发布与升级的结果进入现有绑定和任务查询，不依赖独立浏览器配置库。

## 实施与验收

按契约/迁移、服务端管理与解析、执行快照、桌面页面、浏览器验收推进。手机端暂缓，云执行及权限议题不扩展。原型验收与正式服务验收分开记录；原型通过不代表生产 API、数据库或模型执行已经通过。[验收文档](ACCEPTANCE.zh-CN.md)列出可复现操作及正式实现必须补齐的检查。
