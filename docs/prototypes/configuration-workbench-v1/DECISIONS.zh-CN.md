# 配置原型交互决策

2026-10-05。依据[原型评审](REVIEW.zh-CN.md)与用户逐项选择整理，作为下一版桌面原型及后续 OpenSpec 的设计输入。以下是已确认的设计；当前 HTML、截图及评审证据仍对应 v1，尚未实现这些调整。

## 已确认的选择

### ① 成员资源包选择显式区分三种状态

成员访问配置分为「继承群聊全部」「选择部分资源包」「不使用外部资源」。选择部分资源包后，群聊移除相应引用时，只移除失效项；子集变为空时保持为空，提示「当前未选择资源包」，不得自动转为继承全部。

生效集合只能来自群聊当前引用的资源包，配置操作不得因为删除引用而扩大成员范围。空子集与「不使用外部资源」都解析为空集合，但保留各自配置意图。

验收：Bram 仅选择工程开发，群聊移除工程开发后，Bram 的资源集合为空，不能获得资料研究；用户明确切换为继承全部后，才使用群聊其余资源包。

### ② Bundle 固定版本，通过独立动作升级

群聊继续使用已引用的固定版本。选择器和详情统一显示「当前 v2 / 最新 v3」，普通选择确认不得隐式升级；通过独立升级按钮确认后，才切换引用版本。

验收：发布工程开发 v3 后，原有群聊仍使用 v2；打开选择器并确认仍为 v2；执行明确升级后才变为 v3。

### ③ Agent 与 Skill 固定发布版本

Agent 提示词、Skills 等配置使用固定发布版本。已有群聊不会因 Agent 或 Skill 发布新版而自动变化，需要明确升级。Skill 引用需记录版本，不能只记录 ID 后读取最新内容。

Agent、Skill 和 Bundle 的升级只影响后续新任务。运行中的任务继续使用创建时固定的定义、Binding 与资源配置快照，保持现有 Task 数据流。

验收：发布 Agent 或 Skill 新版后，已有群聊保持原版本；群聊升级后，新任务使用新版，已有任务的快照仍为旧版。

### ④ 语言按单向优先级解析

优先级为「群内 Agent 单独设置 → 群聊明确语言 → Agent 默认语言 → 工作区默认语言」。继承或跟随选项表示该层未指定具体语言，继续向后解析，不能跳回已经检查过的层。

生效预览展示具体语言及来源，不展示未解析的「继承群聊」作为最终值。工作区默认应有具体语言；缺失时使用产品的明确默认语言作为终点。

验收：群聊指定中文、Agent 默认英文、成员未单独指定时，生效为中文，来源为群聊；成员单独指定英文时生效为英文；所有上层均继承时落到工作区默认。

### ⑤ 连接显式身份优先于 Bundle 默认身份

Bundle 身份是默认值。MCP 或 GitHub 连接明确指定身份时使用连接身份；连接未指定时才继承 Bundle 默认身份。域名配置不因引用 Bundle 而获得登录凭证。

生效预览逐资源展示类型、来源包与版本、实际身份及其来源、实际操作范围。MCP 展示工具清单，域名展示域名和端口，GitHub 展示仓库、分支、路径与动作。

验收：Bundle 默认身份为专用项目账号，MCP 显式指定 Cumora 服务账号、GitHub 显式指定 Cumora GitHub App 时，预览分别显示后两者；未指定身份的连接才显示继承的专用项目账号。

### ⑥ 手机端暂不纳入本轮范围

本轮只推进桌面原型。R7 窄屏导航裁切继续保留为已知问题，暂不选择或实施手机端导航方案，也不列入本轮验收完成条件。

## 明确缺陷的修复口径

- R2：撤销新建对象后，重新校验选中对象，回到有效对象或空状态；同步详情、标题与导航状态，编辑事件检查对象存在。
- R4：从 Skill 选择器导入时保留成员上下文与未提交选择；导入成功返回原选择器并选中新 Skill，由用户确认整组选择。

上述两项沿用交互讨论中的修复口径，无需新增产品选项。原型评审中的 R1、R3、R5、R6 按已确认选择处理，Agent/Skill 版本策略补齐原评审的设计待明确项。

本轮仍沿用群聊即 Channel、默认 Aida 与本地计算机验证范围；云执行和权限议题继续不纳入本轮讨论。
